# Замеры меню — 20 ноября 2026

Проверены AdrenalinGUI из коммита `a5cc7a3`, BMenu 2.7 и AbstractMenus 1.18.0. Цель — сравнить повторное открытие одинаковых меню и выполнение одинаковой кнопки, а не определить максимальное количество игроков.

## Условия

- Paper 1.21.11 build 132, Java 21.0.11, Windows 11
- Intel Core i5-12400F, 16 ГБ RAM, heap сервера 1–2 ГБ
- 8 Mineflayer-ботов на том же ПК; Rust закрыт на время измерений
- Все три движка загружены одновременно; сценарии выполняются последовательно
- BLibV2: официальный файл релиза 1.7.9; внутри он сообщает версию 1.7.8
- PlaceholderAPI 2.12.3, WorldEdit 7.4.2; точные SHA-256 — в [окружении](results/2026-11-20/environment.json)
- У всех окон 54 предмета PAPER, четыре строки описания и одинаковые legacy-цвета
- Динамический вариант: `%bench_name%` в заголовке/названиях, `%bench_value%` в описании; собственное расширение возвращает имя игрока и число 100
- 30 прогревочных открытий на бота для каждого из шести вариантов; затем 3 раунда по 50 открытий на бота с перестановкой порядка
- Итого 7 200 измеренных открытий и 7 200 измеренных действий; по 1 200 на каждую комбинацию движка и сценария

## Что измерено

`open` — `System.nanoTime()` вокруг обычного публичного API открытия меню. Сюда входит создание/рендер и замена предыдущего окна, но не доставка пакетов и отрисовка клиента. Синтаксический разбор файлов при запуске и холодный первый вызов исключены прогревом.

`click_action` — от обработчика `InventoryClickEvent` с приоритетом LOWEST до исполнения одинаковой команды `benchack` от имени игрока. AdrenalinGUI запускает свой обработчик на следующем тике; этот интервал намеренно включён. Это не изолированная стоимость одной функции и не сетевой ping.

Боты проверяют все 54 полученных предмета: материал, количество, название, цвет и четыре строки описания. Проверка выполняется на клиенте, потому что BMenu использует пакетное представление инвентаря. За прогон с прогревом проверены 8 640 окон и 466 560 предметов, ошибок — 0.

Сырые наносекунды: [samples.json](results/2026-11-20/samples.json).
Итоги и отдельные раунды: [summary.json](results/2026-11-20/summary.json).
Подтверждение клиентских проверок: [client-run.json](results/2026-11-20/client-run.json).

## Ограничения

Это один прогон на рабочем ПК, а не независимый бенчмарк, JMH или тест TPS. Боты и сервер делят CPU и память. Различия отдельных раундов видны в JSON; агрегированная медиана не доказывает превосходство на другом железе.

Все три плагина остаются загруженными. Их фоновые задачи и обработчики событий могут влиять на общий сервер, поэтому эти результаты нельзя использовать для сравнения полной стоимости каждого плагина в отдельной JVM.

Стартовые HTTP(S)-проверки и загрузки JVM направлены на закрытый локальный прокси. Необязательный мост старого BMenu 1.7 не удалось загрузить; конструктор BMenu перехватывает эту ошибку. Нативные меню BMenu 2.7 прошли клиентскую проверку. Старые меню 1.7, анимации, листовые каталоги, сторонние расширения экономики, горячая перезагрузка и Bedrock не проверялись.

В выбранных настройках релизов текст с MM-тегами не совпал визуально, поэтому для одинакового результата все три набора фикстур используют legacy. Это не отдельный тест скорости MiniMessage.

## Повторение

1. Соберите публичный AdrenalinGUI: `./gradlew clean build`.
2. Скачайте в локальную папку `assets` официальные артефакты ниже и сравните их с SHA-256 из JSON.
3. Создайте отдельный сервер, привязанный к `127.0.0.1`. Подтвердите EULA Minecraft самостоятельно. Скопируйте настройки из `fixtures/server.properties`; изменения `spigot.yml` приведены отдельно.
4. В `plugins` положите три меню-плагина, BLibV2, PlaceholderAPI и WorldEdit. Файлы `bmenu_*.yml` скопируйте в `plugins/BMenu/menu`, `bench_*.conf` — в `plugins/AbstractMenus/menus`.
5. Соберите измерительный плагин из корня публичного проекта:
   `./gradlew -p benchmarks/harness -PbenchmarkAssets=/absolute/path/to/assets build`.
   Положите `benchmarks/harness/build/libs/MenuBenchmark.jar` в `plugins`.
6. Запустите Java 21 с аргументами из `environment.json`. Для отключённых сетевых загрузок необходимые зависимости должны уже быть в локальном кэше. В частности, BLib использует Caffeine 3.2.4.
7. В `benchmarks/bots` выполните `npm install --no-audit --no-fund`. Проверенные версии: Node 24.19.0, Mineflayer 4.39.0, minecraft-protocol 1.68.0, minecraft-data 3.119.0. Транзитивные версии при будущей установке могут отличаться.
8. Проверьте готовность сервера и остановите постороннюю тяжёлую нагрузку. Выполните `node benchmarks/bots/run.cjs`. Сначала можно задать `BENCH_SMOKE=1` для короткого контрольного прогона.
9. Сервер запишет `plugins/MenuBenchmark/results.json`. Скопируйте его как `samples.json` и выполните `python benchmarks/summarize.py /path/to/samples.json`.
10. Завершите сервер штатной командой `stop`. RCON-пароль в фикстуре предназначен только для локального стенда; не используйте эти настройки на публичном сервере.

`BENCH_BOTS_ROOT` позволяет указать другую папку с установленным Mineflayer. `BENCH_OUTPUT_DIR` задаёт путь клиентского отчёта, `BENCH_RCON_PASSWORD` — пароль RCON. Исходный прогон не изменялся; дополнительные наборы приведены отдельно ниже.

## Оптимизация и прогоны под сторонней нагрузкой

Исходный набор выше сохранён без изменений. Для текущего кода выполнены дополнительные приблизительные прогоны с запущенным Rust, который занимал около 8 ГБ. Использованы те же сервер, меню, восемь ботов, 30 прогревочных открытий и три раунда по 50 открытий на бота. До прогрева команда `benchverify Bench0` проверяет динамический callback, отдельные слоты refresh, удаление зачарования, отсутствие лишних lifecycle-событий и актуальные значения при повторном открытии (`BENCH_VERIFY=1`).

Финальный прогон: [samples](results/2026-11-20-loaded-v2/samples.json), [summary](results/2026-11-20-loaded-v2/summary.json), [клиентские проверки](results/2026-11-20-loaded-v2/client-run.json), [окружение и отпечатки исходников/JAR](results/2026-11-20-loaded-v2/environment.json). Все 7 200 открытий и 7 200 действий записаны; 466 560 проверок предметов прошли.

Промежуточная итерация до компиляции токенов и упрощения ключа кэша: [samples](results/2026-11-20-loaded/samples.json), [summary](results/2026-11-20-loaded/summary.json). Здесь для `agui/dynamic/click_action` записано 1 198 образцов из 1 200. Причина двух отсутствующих записей отдельно не установлена; они не считаются нулевой задержкой. В промежуточном прогоне были полные наборы открытий и успешные клиентские проверки, но неполная метрика кликов.

По умолчанию summarize.py отвергает неполный набор. Явный флаг `--allow-incomplete-actions` разрешает только неполную метрику кликов и сохраняет её в `incomplete_actions`; отсутствующие открытия и ошибки стенда по-прежнему запрещены. Финальный прогон проходит и без этого флага.

Бот теперь ждёт до пяти секунд доставки всех предметов перед проверкой содержимого; интервал серверного `nanoTime` не изменён. Нагрузка игры, возможная подкачка и различия между раундами не позволяют трактовать разницу с исходной сборкой как чистое ускорение от кода. Текущая медиана открытия с плейсхолдерами: AdrenalinGUI 0,217 мс, BMenu 0,206 мс, AbstractMenus 0,578 мс. Первое место по всем метрикам не заявляется.

## Проверка анимаций

После сборки текущего AdrenalinGUI и harness на локальном стенде задайте `BENCH_ANIMATION_ONLY=1` и запустите `node benchmarks/bots/run.cjs`. Этот режим подключает двух ботов и проверяет hide/show, change/set, повторение, сохранение состояния при refresh, независимость окон, отмену задач при закрытии и смене страницы, обработчик заменённой кнопки и отбрасывание устаревшего клика. Это функциональная проверка, а не новый замер производительности. Результат можно получить командой RCON `benchanimationstatus`.
