## Стенд

- Paper 1.21.11 build 132 и Oracle Java 21.0.11+9-LTS.
- Windows 11, Intel Core i5-12400F, 16 ГиБ RAM, heap сервера 1–2 ГиБ.
- Сервер и восемь Mineflayer-ботов работают на одном ПК.
- Rust закрыт. Обычная рабочая сессия Windows остаётся активной.
- Все три движка загружены в одной JVM, сценарии запускаются последовательно с перестановкой порядка между раундами.
- Используются BLib, PlaceholderAPI и WorldEdit из сохранённого набора. Точные SHA-256 находятся в environment.json.

## Одинаковые меню

Окно содержит 54 предмета PAPER по одной штуке. У каждого предмета название и четыре строки описания.

В статичном сценарии текст постоянный. В сценарии с плейсхолдерами в название подставляется имя игрока и индекс слота, в лор — постоянное значение. Во всех трёх наборах используется legacy для одинакового видимого результата.

Нажатие на слот 13 выполняет одну и ту же команду benchack. Боты проверяют все полученные предметы, включая материал, количество, название, цвет и лор. Это необходимо и для пакетного представления BMenu.

## Границы метрик

open измеряется через System.nanoTime вокруг обычного API открытия меню. Он включает серверное создание и рендер, замену предыдущего окна. Доставка пакетов и отрисовка клиента за его пределами. Синтаксический разбор конфигураций исключён прогревом.

click_action начинается при получении InventoryClickEvent на LOWEST и заканчивается при исполнении команды benchack. В AdrenalinGUI сюда входит отложенный запуск действия на следующем тике.

Это тест повторного открытия конкретных меню и задержки действия. Сервер и боты делят CPU и память, все три движка загружены одновременно. Результат не определяет предельный онлайн или стоимость движка в отдельной JVM.

Стартовые HTTP(S)-проверки направлены на закрытый loopback-прокси. Необязательный мост BMenu 1.7 недоступен. Нативные меню BMenu 2.7 прошли клиентскую проверку.

## Повторение

1. Подготовьте изолированный сервер на 127.0.0.1 с официальными артефактами из environment.json. Используйте Java 21 и настройки из fixtures.
2. Положите BMenu, AbstractMenus, BLib, PlaceholderAPI, WorldEdit и проверяемый AdrenalinGUI в plugins.
3. Скопируйте bmenu_*.yml в plugins/BMenu/menu, bench_*.conf — в plugins/AbstractMenus/menus.
4. Соберите harness, передав каталог сторонних артефактов и путь проверяемого AdrenalinGUI.

```bash
./gradlew -p benchmarks/harness build \
  "-PbenchmarkAssets=/absolute/path/to/assets" \
  "-PaguiJar=/absolute/path/to/AdrenalinGUI-2.0.1.jar"
```

5. Положите benchmarks/harness/build/libs/MenuBenchmark.jar в plugins. Запустите сервер с аргументами из environment.json.
6. Установите зависимости ботов через npm install в benchmarks/bots. Проверенные версии Mineflayer 4.39.0 и minecraft-protocol 1.68.0.
7. Выполните BENCH_VERIFY=1 node benchmarks/bots/run.cjs. В PowerShell задайте переменные через $env.
8. Сохраните plugins/MenuBenchmark/results.json как samples.json и клиентский client-run.json из каталога вывода.
9. Запустите python benchmarks/summarize.py /path/to/samples.json. Завершите сервер штатной командой stop.

BENCH_BOTS_ROOT позволяет использовать отдельный каталог зависимостей. BENCH_OUTPUT_DIR задаёт каталог клиентского отчёта, BENCH_RCON_PASSWORD — пароль локального RCON. Учётные данные в fixtures предназначены для локального стенда.

## Функциональные проверки

Режимы BENCH_ANIMATION_ONLY, BENCH_GUIS_ONLY и BENCH_INTERACTION_ONLY в benchmarks/bots/run.cjs проверяют анимации, команду /guis info и типизированный ввод с историей меню.

Команды benchverifyinventory, benchverifyinputs и benchverifyrules измерительного плагина предназначены для серверных проверок инвентаря, связанных полей, фильтров, событий и условий кнопок. Они используют тестового игрока Bench0.

Архивные сырые прогоны сохранены в results. Текущая контрольная выборка приведена выше.
